# Ф3 — Т-Банк (T-API, выписка по расчётному счёту)

Разведка и реализация, 2026-07-26. Источник: [developer.tbank.ru](https://developer.tbank.ru/docs/api/t-api).
Контракт проверен **живым прогоном по песочнице** (не только по документации).

## Метод и авторизация

```
GET {base}/v1/statement?accountNumber=&from=&to=&cursor=&limit=&operationStatus=
Authorization: Bearer {token}
```

- Пром: `https://business.tbank.ru/openapi/api`
- Песочница: `https://business.tbank.ru/openapi/sandbox/api` — **доступна без
  доступов и сертификата**, токен фиксированный: `TBankSandboxToken`.
  Отвечает заранее заданным телом: годится для проверки формата и ошибок, не
  для проверки бизнес-данных.
- Токен для прома: ЛК Т-Бизнеса → Интеграции → Выпуск токена → доступ
  **«Счета и выписки»** (обе галки: информация о счетах и об операциях).
- Лимит 20 запросов в секунду. Данные доступны с июня 2023 года.

Т-Банк заметно проще Альфы: нет mTLS, период произвольный (а не один
календарный день), контрагент лежит готовым блоком `counterParty` с ИНН, а
список счетов можно получить методом `/v4/bank-accounts`.

## Три вещи, определяющие корректность учёта

1. **Холды не проводим.** Операция бывает в статусе `Authorization`
   (средства заморожены, баланс не изменён) — банк прямо пишет, что в
   бухгалтерскую отчётность их отдавать нельзя. Запрашиваем
   `operationStatus=Transaction` и перепроверяем статус при разборе.
2. **Дата — `operationDate`** (проведение по балансу банка, 71-е поле по 862-П).
   У операции есть ещё четыре даты (`docDate`, `authorizationDate`,
   `trxnPostDate`, `chargeDate`/`drawDate`); для отчётности годится только эта.
3. **`Credit` — приход, `Debit` — расход** (банк: `credit` ↔ `income`,
   `debit` ↔ `outcome` старого API).

## Курсор и окно перекрытия

Операция доходит до финального статуса **3–4 дня**, и `operationDate` при этом
оказывается в прошлом. Поэтому курсор — не «граница, дальше которой не
смотрим»: `syncCursor` хранит дату последней операции, а каждый синк
запрашивает период начиная с **курсор минус 7 дней** (`LOOKBACK_DAYS`). Без
этого операции, доехавшие задним числом, терялись бы навсегда.

Курсор двигается только вперёд и только по факту операций: пустой ответ его не
сдвигает. Дубли, порождённые перекрытием, отсекаются дважды — в самом адаптере
(по `operationId` в пределах синка) и идемпотентностью
`(connectionId, externalId)` в `SyncService`.

## Что нашёл живой прогон (чего не показали моки)

1. **Бесконечный цикл пагинации.** Песочница отдаёт `nextCursor` всегда — даже
   когда добирать нечего. Адаптер крутил запросы до потолка страниц и падал.
   Исправлено: цикл останавливается, если курсор не изменился, страница пустая
   или курсора нет. На проме это тот же класс защиты.
2. **Токен с кириллицей роняет HTTP-клиент.** Заголовок `Authorization` —
   latin1, и токен с пробелом, переводом строки или кириллической буквой давал
   техническое `Cannot convert argument to a ByteString`, которое доезжало до
   владельца как невнятный текст в статусе подключения. Теперь ключ проверяется
   до запроса (`assertHeaderSafe` в `bank-http.ts`) и обоим банкам выдаётся
   человеческое сообщение.

Проверено на живом API также: неверный токен → 401, номер счёта не из 20 цифр →
400 с `errorId` (банк просит его логировать — он попадает в текст ошибки как
«код обращения»).

## Известный риск

`operationId` **может измениться** у операций, проведённых с 22:00 до 03:00
(документация банка). Наша идемпотентность держится на нём, значит одна операция
теоретически способна прийти дважды под разными id и создать дубль строки в
«Входящих». Вторая линия дедупа (дата + сумма + назначение) пока не заложена —
кандидат в бэклог, если дубли проявятся на реальном счёте.

## Не сделано (осознанно)

- **Вебхук «Операция по счёту»** — push вместо часового опроса. Подключается
  письмом на `openapi@tbank.ru` (ИНН, событие, URL, данные авторизации),
  тестового режима нет. Имеет смысл, если операций много или нужна мгновенная
  реакция; сверку выпиской банк всё равно рекомендует оставить.
- **Выбор счёта из `/v4/bank-accounts`** вместо ручного ввода 20 цифр — метод
  работает (проверено в песочнице), но требует UI-шага «выбрать счёт после
  ввода токена». Пока номер вводится руками, как у Альфы.

## Настройка

Песочница (локально или на сервере):

```
TBANK_API_BASE_URL=https://business.tbank.ru/openapi/sandbox/api
```

В приложении: **Интеграции → Подключить банк** → Т-Банк, счёт,
номер `40702810510000710417`, токен `TBankSandboxToken`.

Пром: `TBANK_API_BASE_URL` не задаётся (по умолчанию `https://business.tbank.ru/openapi/api`),
токен из ЛК вводится в UI. На сервере обязателен `INTEGRATION_MASTER_KEY` —
иначе модуль интеграций отвечает 503.

тесты — `tbank.adapter.test.ts`. Про Альфу — [`alfa-api.md`](./alfa-api.md).
