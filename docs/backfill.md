# Перезалив истории из банка

Как забрать в приложение операции, которые банк хранит, а мы ещё не загрузили —
не задвоив то, что уже внесено вручную.

## Зачем понадобилось

Адаптеры стартовали с даты подключения (решение №15 генплана: «прошлое занесено
руками»). После подключения Альфы выяснилось, что прошлое всё-таки нужно: банк
хранит 5 лет, а в базе за май–июль лежали ручные записи без реквизитов
контрагентов. Первый план был «вычистить базу и залить заново» — ценой склада,
заказов и привязок оплат. Вместо этого приложение научили **узнавать** свои
операции в приезжающих строках.

## Как работает узнавание

При загрузке каждой строки, до применения правил, ищется операция, которая уже
есть в базе:

1. **По отпечатку** (`importHash`) — та же операция уже импортирована из CSV.
   Самая надёжная ступень, поэтому первая.
2. **По содержимому** — тот же счёт, направление и сумма, дата в пределах
   **±5 дней** (ручные записи датируют приблизительно, банк — точно). Операция
   не должна быть привязана к другой строке и не должна быть неденежной
   (`COGS`, `WRITE_OFF`).
3. При нескольких кандидатах: сначала совпадение по **ИНН**, затем ближайшая по
   дате. Внутри одной загрузки одна операция достаётся только одной строке.

Что происходит при совпадении: строка получает статус «обработана» и ссылку на
существующую операцию. **Новая проводка не создаётся, правила не применяются** —
разметка человека главнее. Пустые поля операции дозаполняются из выписки
(контрагент по ИНН — с созданием справочника, маркировка АУСН); заполненное
человеком не трогается.

Отмена такой связи (кнопка «Отменить связь» во «Входящих» → «Обработано») только
отвязывает строку: операция остаётся. Это отличает узнавание от авто-проведения
правилом, где отмена снимает и проводку.

## Порядок действий

1. **Снять свежий дамп прода** — точка отката и источник контрольных итогов:
   ```
   ssh -i ~/.ssh/deploy_ferrum root@195.133.1.13 \
     'docker exec construct-v6-postgres-1 pg_dump -U construct construct_v6' | gzip > snapshot.sql.gz
   ```
   Записать до начала: число операций и денежные средства с дашборда.

2. **Репетиция на копии.** Развернуть дамп в отдельную базу, применить миграции,
   прогнать загрузку и сверить: число операций и денежные средства **не меняются**,
   строки истории приходят со статусом «узнана». Скрипт репетиции — в заметках
   сессии 2026-07-30 (`rehearsal-final.ts`): он снимает «выписку» с реальных
   операций снапшота, сдвигает даты на день и проверяет итоги.

3. **Задать дату** в карточке подключения (Интеграции → «Выписка с …»). Сдвиг
   назад сбрасывает курсор, поэтому следующая загрузка пойдёт за историей.

4. **Жать «Обновить», пока история не догонит.** Альфа отдаёт выписку по одному
   календарному дню, за проход берётся не больше 31 дня — за май–июль нужно
   несколько нажатий. Ориентир в тосте: «Загружено: N, узнано ранее внесённых: K».

5. **Сверить** с записанными в п.1 итогами: денежные средства обязаны совпасть.
   Расхождение = ровно сумма операций, которых в базе не было; они лежат во
   «Входящих» на разборе.

6. **Разобрать остаток** — правилами (Отчёты → Правила → предпросмотр →
   «Применить правила») либо вручную во «Входящих».

## Чего ждать

- **Карты ВБ история не вернёт**: `ВБ Антропов …4510` и `ВБ Каменск …8975` — карты
  физлиц, API их не отдаёт (58 операций). Только ручной ввод или PDF-разбор.
- **Переводы между своими счетами** приедут двумя независимыми строками (расход
  с одного счёта, приход на другой) и задвоят обороты, пока их не свяжут в
  перевод. Автоматического спаривания пока нет.
- Т-Банк отдаёт операции с июня 2023, Альфа — 5 лет от 1 января текущего года.
