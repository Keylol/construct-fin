## Готовы к фиксу

### 1. CSV formula injection — `export/csv.ts:5-11` · sound
`escapeCsv` экранирует только разделители, но не ведущие `= + - @ TAB CR`. Атакуемы свободнотекстовые поля
(имена контрагентов/категорий, title) в мультитенанте.
**Фикс:** `sanitizeFormula()` префиксует опасный ведущий символ апострофом `'`, **только для text-ячеек**
(`c.kind==='text'`) — деньги/числа/проценты не трогаем (отрицательные суммы не ломаются).
**Капкан реализации (от скептика):** внутри `escapeCsv` заменить ВСЕ обращения к `value` на
санитизированный `v` (строки `if(v==='')`, `regex.test(v)`, `v.replace`), иначе значение `'='` без
разделителей вернётся без префикса — фикс обнулится. Добавить `csv.test.ts`.

### 5. WorkspaceGuard не проверяет deletedAt — `workspace.guard.ts:36-43` · sound
Гвард авторизует только по `WorkspaceMember`, не смотрит `Workspace.deletedAt`. `softDelete` помечает только
сам Workspace, member-строки живут → после `DELETE /workspaces/:wsId` все **68 маршрутов** остаются рабочими
(хотя ws пропал из листинга).
**Фикс:** в гварде грузить workspace через `include` и при `deletedAt != null` бросать **404** (не 403 —
чтобы не светить, что ws существовал). Один запрос, все 68 маршрутов чинятся автоматически. Нужен тест гварда
(member active→ok, non-member→403, member deleted→404).
**Решение продукта:** 404 (рекомендую, как в service-слое) или 410 Gone.

### 3. Инвалидация кэша денег — `hooks/*` · incomplete (ядро верно)
Денежные мутации (оплата/закупка/импорт/транзакции) инвалидируют узкие ключи; отчёты/сводки/склад/сверка
остаются из кэша → устаревшие деньги на экране.
**Фикс:** единый хелпер `invalidateMoneyViews(qc, wsId)` (`lib/invalidate.ts`), звать из всех денежных мутаций.
**Тонкость (подтверждена кодом):** TanStack матчит ключ префиксом, а ключи отчётов — `['reports', kind, wsId, ...]`
(wsId не на позиции 1), поэтому отчётные семейства инвалидируем по корню `['reports']`/`['trade-reports']`/`['reconciliation']`.
**Закрыть 4 пробела:** `useTransfers` не гасит `reconciliation`; дополнить список мест; учесть, что корневая
инвалидация бьёт по всем ws (перф, не корректность).

## Требует доработки спеки

### 2. parse-amount — `parsers/values.ts:9-27` · FLAWED ⚠
Деньги из выписки идут через `Number()+toFixed` (не half-up: 2.675→2.67), и эвристика разделителей даёт
1000x на `'1,234'` (US).
**Половина фикса верна:** нормализация через `money()` (Decimal half-up) — правильно.
**Дефект предложенного фикса (скептик):** дефолт «единственный разделитель + 3 цифры → группировка/целое»
создаёт ЗЕРКАЛЬНЫЙ silent 1000x: `'2.500'` → `2500.00` вместо `2.50`. Бьёт по `wb-pdf.ts` и `alfa-xlsx.ts`
(вызываются без `decimalSep`).
**Что нужно:** при подлинной неоднозначности — возвращать `null` (не угадывать); явно пинить `decimalSep`
в парсерах wb/alfa; прогнать на фактических фикстурах. **Спеку переписать перед любым кодом.**

## Ждёт решения продукта

### 4. Границы скидки заказа — `order.service.ts:58-60` + `order.dto.ts` · incomplete
`MoneyString` допускает ведущий минус; клэмпа нет. Отрицательная скидка раздувает `totalAmount` выше subtotal;
скидка > subtotal → отрицательный `total` → `syncPaymentState` ломается (оплаченный заказ показывает `OVERPAID`,
неоплаченный не достигает `PAID`).
**Фикс (два слоя):** zod — отдельный `NonNegMoneyString` (как у `refundAmount`) для `discountAmount` в Create+Update;
сервис — приватный гвард `0 ≤ discount ≤ subtotal`, бросает `BadRequestException` (как `ship`/`returnItem`).
`discount == subtotal` (total=0) — валидно.
**Важный edge (скептик):** в update-с-items валидировать против НОВОГО subtotal даже если `discountAmount`
не пришёл в payload (старая валидная скидка может превысить новый subtotal).
**Решение продукта:** при редактировании заказа, когда новый `total` падает ниже уже оплаченного `paidAmount`
→ молча флипать в `OVERPAID` или отклонять правку? Существующие битые строки — отдельный backfill.

## Решения Александра (2026-06-24, зафиксированы)
- **#5:** на soft-deleted workspace возвращать **410 Gone** (не 404).
- **#2:** при подлинно неоднозначном разделителе — **отклонять строку (null)**; где банк известен (Альфа/WB/Тинькофф) — пинить `decimalSep` явно, чтобы неоднозначности не было.
- **#4:** скидки используются; диапазон `0 … subtotal`; правку, дающую итог ниже уже оплаченного, **отклонять** (`BadRequest`, «сначала оформите возврат») — не плодить фантомный OVERPAID.
- **Режим:** сначала всё спроектировать, код — одним пакетом потом.
