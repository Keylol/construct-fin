# Council-аудит: реестр находок (поблочный)

Формат: глубокий совет — 2 искателя (линзы: инварианты данных / конкурентность+край) → 3 линзовых скептика (корректность/безопасность/эксплуатация), порог ≥2 голосов «real» → критик полноты → добор.
Карта-опора: [architecture-map.md](architecture-map.md). Статусы: `confirmed` (совет ≥2), `unverified` (совет не прошёл — лимит), `fixed`.

### Главные выводы (честно)

1. **Денежный леджер (таблица Transaction) сам по себе корректен.** Почти все находки — это (а) read-модели, считающие по сырому totalAmount/статусу вместо netQty, (б) дыры валидации входа (знаки, даты, категории), (в) generic-CRUD шины, обходящий доменные инварианты. Ядро FIFO/UoW/локов держится.
2. **Ни одной эксплуатируемой межтенантной дыры.** Auth-ядро (HMAC/JWT/workspace-guard) и изоляция подтверждены. Прод-посадка безопасна (allowlist задан, секрет 128 симв.).
3. **Ни одной необратимой порчи денег или потери данных.** Off-site бэкап подтверждён фактом. HIGH-флаги совет темперировал до medium — ущерб ограничен (read-модель, само-лечение, масштаб 1-2 юзера).

### Три сквозные темы

- **A. Обратимость операций** — почти нет undo/исправления (C2, F1/F2, GH8, GH9, оплаты). Александр выбрал доменные undo-пути для каждого → отдельный пакет работ.
- **B. Согласованность отчётов** — read-модели считают один факт по-разному (grossProfit, скидка, даты, ярлыки, бакеты). Формульные фиксы + 1 design-item (IJ9 closedAt-базис P&L).
- **C. Наблюдаемость** — нет мониторинга/алертинга, health слеп к БД, нет ротации логов → сегодняшнее падение VPS заметили случайно. Операционный приоритет.

### План исправлений по волнам

**Волна 1 — Целостность денег и изоляция:** C1 (блок generic-мутаций строк с transferGroupId + kind в serialize), C16 (сверка kind↔type), F1/F2 (блок delete/archive с остатком), C3 (единый kind-фильтр в reconciliation), DE3 (positivity-guard addPayment), DE5 (кап рефанда), C6/F6 (идемпотентность денежных POST), DE4 (границы дат).

**Волна 2 — Обратимость (доменные undo, согласовано):** C2 (удаление оплаты), GH8 (откат импорта), GH9 (void закупки нетронутых лотов), DE6 (чистка вложений).

**Волна 3 — Согласованность отчётов:** IJ2 (grossProfit=REVENUE.net−COGS), IJ1 (скидка в марже), IJ3 (CAPITAL из headline), F5 (WRITE_OFF из net), DE1 (дебиторка netQty), DE2 (CANCELLED из receivables), IJ5/6/7/10/11 (периоды/isoDate/подписи). Отдельно: IJ9 (P&L на closedAt — design-item).

**Волна 4 — Наблюдаемость и деплой:** L2 (health честный к БД), L4/L5 (ротация логов + disk/5xx-алерты), L1 (migrate до up -d), L3 (web в health-gate), L6 (TLS на живой домен + DNS-хвосты), L7 (graceful shutdown), L8 (пул/таймауты Postgres).

**Волна 5 — Hardening + UX:** фронт-инвалидации (K1-K4), fire-and-forget ошибки (K5/K9), export/upload (K11/K12), мобильный (K13, ср. приоритет); auth logout/аудит (AB5/AB6/C20), fail-closed дефолт (AB7/AB8); парсеры (GH3/GH5/GH6/GH7); прочие LOW.
