# Construct v6 — генеральный план доработок

**Дата:** 2026-06-07
**Цель:** довести текущую версию до общей оценки ~7.25 (минимум 7) минимальными, обратимыми шагами, без риска уронить прод. ERP-ядро (двойная запись, главная книга, закрытие периода) **намеренно не трогаем** — дорого и вне задачи.

## Целевые баллы по блокам

| Блок | Сейчас | Цель | Чем поднимаем |
|---|---|---|---|
| Тесты + эксплуатация | 5.5 | **7.5** | бэкап, тест-гейт, мониторинг, лимиты, снапшот перед миграцией |
| Безопасность | 6.5 | **8.0** | заголовки nginx, ротация секретов, огородить пароль, TTL токена |
| Бэкенд | 7.0 | **8.0** | глобальный exception filter + ValidationPipe, bucket/kind в DTO |
| Модель данных | 6.0 | **7.0** | unique-индекс на импорт, идемпотентность, FOR UPDATE, дедуп COGS |
| ERP-полнота | 4.0 | **5.0** | энфорс ролей, UI аудита, явная фиксация cash-basis |
| Фронтенд | 8.0 | 8.0 | оставляем |

**Среднее: 43.5 / 6 = 7.25.**

## Принятые решения (развилки)

- **COGS в P&L → cash-basis + дедуп.** Расход признаётся в момент закупки (как сейчас), но убираем двойной счёт суммы (expense / cogs / OTHER сводим к одной классификации) и явно документируем учёт как cash-basis. Капитализацию запасов НЕ делаем.
- **Password-вход → огородить через allowlist.** Пароль оставляем, но прогоняем через тот же `TELEGRAM_ALLOWED_IDS` (сейчас он этот контроль обходит). Десктоп-вход продолжает работать.

## Сквозные правила «чтобы не упало»

- Каждая фаза — отдельный деплой, независимо откатываемый. Никаких больших PR «на всё сразу».
- Любая фаза с кодом мёржится только после зелёного CI (после Фазы 0 — жёсткий гейт).
- Перед каждой миграцией — `pg_dump` (автоматически в пайплайне) + прогон на копии БД.
- Миграции только аддитивные (новые поля/индексы), без `DROP`/переименований данных.
- После каждого деплоя — проверка `/health` + smoke (`/login`); при красном — авто-стоп и откат на предыдущий `:sha`-тег образа.
- Единственное заметное пользователю действие за весь план — ротация `JWT_SECRET` (разлогинит 1–2 владельцев). Делаем в тихое окно, предупреждаем.

16. **Аудит + блокировка правки системных транзакций** — `transaction.update` (`apps/api/src/transaction/transaction.service.ts`) сейчас не пишет AuditLog и позволяет менять `ORDER_PAYMENT`/`PURCHASE`/`COGS` в обход инвариантов. Запретить менять `kind`-системные, логировать апдейты.

Риск: средний. Каждый пункт — отдельный PR + тесты на сервисный слой (сейчас 0). Exception filter проверяем на сохранение существующих контрактов ответов.
