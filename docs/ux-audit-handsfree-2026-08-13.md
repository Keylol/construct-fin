# Аудит флоу заведения заказов: курс на работу руками, без агента

Дата: 2026-08-13. Материал: 21 заказ июля (3,9 млн выручки), проведённый через UI за
сессии 09–13.08 — частично руками, частично скриптами агента в консоли браузера. Каждый
скрипт агента здесь читается как дыра в UX: сотрудник без агента в этом месте либо
застрянет, либо потратит в разы больше времени, либо ошибётся.

Вывод в одну строку: **бэкенд готов почти ко всему, не хватает входов из интерфейса.**
Три из четырёх крупных доработок — это кнопки к уже существующим API.

## 1. Где агент подменял интерфейс (фактические замеры)

Время на заказ падало с 52 минут (первый, всё руками+разведка) до 4–9 минут
(отлаженный конвейер со скриптами). Разница — вот эти подмены:

| Шаг | Руками сейчас | Что делал агент вместо этого |
|---|---|---|
| Чтение архива (docx-спецификация, PDF-чеки, заметка) | открывать файлы глазами, приложение не участвует | python: распаковка cp866, парсинг PDF, сверка сумм с реестром |
| Форма заказа: 8 позиций | ~26 полей по одному (название, продажа, закупка × 8 + клиент + название + комментарий) | пакетный JS: вся форма одним скриптом |
| Цена продажи по позициям | посчитать пропорцию к закупке и копейки самому | Decimal-скрипт: пропорция, последняя строка добирает до итога |
| Найти платёж клиента при эквайринге | сумма клиента ≠ сумме в банке (в выписке нетто без комиссии) — поиск «152 506» пуст | поиск по фамилии, конфигу сборки из назначения, фрагменту «Р.ДДММ» |
| Кредит/рассрочка из строки банка | «К заказу» зачитывает нетто → заказ висит недоплаченным | добор оплаты + расход комиссии двумя отдельными действиями |
| Позиции из чека в заказ | механизм wb-receipt есть, но из карточки заказа не достижим | позиции руками, чек не прикреплялся |
| Контроль ошибок | предупреждений нет | SQL-инварианты, контрольные суммы скриптами |

Ошибки, совершённые агентом за сессии — их же совершит человек:

- к заказу Савтикова прицепился чужой платёж 59 737,63 (система позволила привязать
  строку больше остатка без предупреждения; вскрылось только статусом «Переплата»);
- ручные закупки задвоили расход против строк выписки (ДНС/ОТ Мингазова — удаляли);
- комиссии, проведённые «сегодняшним» числом, искажали чужой месяц, пока не появилось
  поле даты (#141).

## 3. Референсы

- **Xero / QuickBooks bank feed**: у строки банка сразу видна *suggested match* с
  существующим документом (сверка по сумме/дате/контрагенту), «Find & Match» собирает
  несколько строк к одному документу. Перенос к нам: подсказка «похоже на оплату заказа
  N» в строке «Входящих» и подбор кандидатов из карточки заказа.
- **Вставка из таблицы**: многолетний топ-запрос пользователей Xero (до сих пор не
  сделан) — перехват paste, TSV → строки позиций. У нас та же боль в форме заказа.
- **Dext / Hubdoc**: фото/PDF → черновик документа с позициями на подтверждение; línea
  извлечения позиций — платная фича Dext. Наш wb-receipt делает то же для наших
  магазинов бесплатно — не хватает только входа в сценарий.

Источники: [QuickBooks: Match transactions](https://quickbooks.intuit.com/learn-support/en-us/help-article/bank-transactions/match-transactions-quickbooks-online/L0MF3Fn6y_US_en_US),
[Xero: Reconcile bank transactions](https://www.xero.com/us/accounting-software/reconcile-bank-transactions/),
[Xero product ideas: paste multiple cells](https://productideas.xero.com/forums/967115-invoices-quotes/suggestions/50923184-invoicing-paste-multiple-cells-into-invoice-line),
[Dext vs Hubdoc](https://eightx.co/blog/dext-vs-hubdoc-receipt-capture).

## 4. Бэклог (приоритет = «сотрудник работает сам»)

### P0 — без этого руками работать нельзя

1. **Вставка состава текстом + распределение цены продажи** (форма заказа).
   Текстовое поле: строка на позицию, «название / закуп [/ продажа]», разделители
   `/`, `|` или tab. Кнопка «Распределить цену продажи»: вводишь итог заказа —
   продажные цены раскидываются пропорционально закупочным, последняя строка добирает
   копейки. Функция распределения — чистая, в `@construct/shared` (рядом с money),
   UI — `apps/web/src/app/(app)/orders/page.tsx`. Убирает ~26 полей ручного ввода и
   весь ручной счёт.
2. **«Найти оплату» в карточке заказа.** Кандидаты из «Входящих» ранжируются по:
   (а) сумма = остатку заказа; (б) брутто-совпадение через parseAcquiringFee;
   (в) ФИО клиента в назначении/контрагенте строки; (г) конфиг сборки из названия
   заказа в назначении. Паттерн реализации — planned-match. Одна кнопка «Привязать»
   у кандидата. Закрывает главный тупик ручной работы: «во „Входящих“ сотни строк,
   какая моя?»
3. **Кредит/рассрочка в диалоге «Привязать к заказу».** Если сумма строки меньше
   остатка заказа — галка «кредит/рассрочка: зачесть {брутто = остаток}, комиссия
   {разница}» → существующий installment-payment одним действием. Убирает ручные
   доборы (Жукова, Смирнов, Галицков, Новаков — 4 случая из 21 заказа за месяц).

### P1 — сильно ускоряет и защищает от ошибок

4. **«Разобрать чек» из карточки заказа**: кнопка → wb-receipt preview с предвыбранным
   заказом; позиции сводного чека выбираются галочками; commit кладёт позиции в заказ
   и привязывает деньги к строке выписки. Вход в готовый механизм.
5. **Три предупреждения**: строка больше остатка заказа («будет переплата N — вы
   уверены?»); ручная «Закупка товара» на счёт с активной интеграцией («счёт получает
   выписку из банка — возможен дубль»); полностью оплаченный открытый заказ — бейдж
   «можно закрыть» в списке.
6. **Диалог закрытия** (находка 14 runbook): кнопку в диалоге переименовать в
   «Подтвердить закрытие», рядом с датой — подсказка «дата последней оплаты: N»
   (наше правило закрытия — по дате денег).
7. **Мелочи навигации**: клик по «Оплата по заказу …» в /transactions открывает
   карточку заказа (сейчас тупик — операция видна, а исправить можно только из
   заказа); фильтр периода в /transactions запоминает последний выбор.

### P2 — перспектива

8. **Мастер «Заказ из архива»**: drag&drop спецификации (.docx, шаблон CONSTRUCTPC
   стабилен: №, исполнитель, заказчик, 9 позиций, итог/предоплата) и чеков → черновик
   заказа с позициями, ценами и привязками. Объединяет P0.1 + P1.4; после него
   заведение заказа = проверка черновика глазами.
9. **Страница «Здоровье месяца»**: незакрытые оплаченные заказы, строки на разборе,
   счета в минусе, дебиторка; сверка остатка счёта с числом из ЛК банка на дату.
10. **Правила для приходов**: действие «подсказать заказ» (сейчас правила ставят
    только категорию/контрагента/счёт).

## 5. Что решено НЕ делать

- OCR сканов и фото — PDF с текстовым слоем уже разбираются, сканы вне скоупа
  (решение 02.08).
- Массовые чекбоксы во «Входящих» — правила закрыли эту боль лучше (214 строк одним
  нажатием, и работают на будущих загрузках).
- Переделка движка правил, FIFO, ОПиУ — работают, не трогаем.

## 6. Мера успеха

Сотрудник без агента заводит типовой архив (8 позиций, 1–2 платежа, 2–4 чека) за
**≤10 минут**, не открывая ничего, кроме приложения; кредитный заказ — одним диалогом;
ошибка «привязал чужой платёж» перехватывается до сохранения. Проверка — живой прогон
с владельцем на одном из оставшихся архивов (Фефелов или Корнеева) после реализации P0.
